# VECTIS Product Identity

## Name

The product name is **VECTIS**.

The owning team identity is **Ghost Five // Spectral Core**.

Use the complete form when establishing context:

**Ghost Five // Spectral Core // VECTIS**

## Product statement

VECTIS is a deterministic automation language and execution toolchain. It is designed for work that needs visible plans, explicit authority, stable diagnostics, and inspectable runtime behavior.

## Voice

The product voice follows the Ghost Five writing standard.

1. Be calm.
2. Be direct.
3. Be technically specific.
4. Describe what the product actually does.
5. Separate implemented behavior from planned work.
6. Avoid filler, artificial enthusiasm, and unsupported claims.
7. Do not use em dashes in prose.

## Interface language

Buttons and commands should use operational verbs such as Check, Plan, Run, Format, Inspect, Test, and Export.

Status text should describe state directly. Use values such as READY, REVIEW, FAILED, BLOCKED, and COMPLETE when those states are accurate.

## Naming

Repository, package, documentation, and application names should keep VECTIS visible. Spectral Core identifies the software team. Ghost Five identifies the larger system and operating standard.
