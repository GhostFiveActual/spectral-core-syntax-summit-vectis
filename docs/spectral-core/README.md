# Spectral Core Standards

## Purpose

This directory is the operating standard for Spectral Core software work. VECTIS is the first full reference implementation because it combines language design, security boundaries, packaging, testing, documentation, user experience, and release discipline in one product.

The standard is simple. A Spectral Core project must be understandable before it is impressive. The repository should explain what the product does, how authority is controlled, how behavior is tested, and what must be true before release.

## Standard set

| Document | Purpose |
| --- | --- |
| Engineering standard | Repository structure, implementation discipline, comments, tests, and quality gates. |
| Writing standard | Ghost Five voice used in documentation and product copy. |
| Language standard | Language design rules learned from VECTIS. |
| Release standard | Versioning, validation, packaging, and release requirements. |
| Knowledge transfer | VECTIS lessons converted into repeatable Spectral Core practice. |

## Authority

These documents are normative for Spectral Core repositories unless a project records a specific exception in its own architecture documentation.

## Operating rule

If a project cannot explain its behavior, test its contract, and identify its authority boundaries, it is not ready to ship.
